# Landing Monitor — светлый прототип центра мониторинга лендингов

Независимый учебный MVP для кейса бизнес-аналитика. Визуальный стиль вдохновлён современными финтех-интерфейсами: **светлый фон, белые панели, чёрная типографика, умеренные жёлтые акценты и векторные иконки**. Это **не официальный продукт Т-Банка**.

В `docs/layout_preview.png` лежит **статичный ориентир по новой компоновке**. Это не скриншот работающего Streamlit: настоящий результат проверь после запуска приложения.

## Что реализовано

- **Обзор:** пять KPI, фильтры периода/устройства/браузера/источника, тренд доступности, диаграмма состояния страниц, инциденты, матрица планируемой проверки платформ, последние проверки, ручная проверка URL.
- **Лендинги:** реестр с поиском, фильтрами и карточкой лендинга.
- **Проверка URL:** реальный ручной HTTPS GET-запрос на разрешённый публичный адрес, HTTP-код, время получения HTML, тег `<form>`, заголовок.
- **Инциденты:** история, приоритеты, ответственные, изменение текущего статуса с сохранением в SQLite.
- **Бизнес-риски:** сценарная оценка расходов на рекламные клики под риском, сортировка кампаний, интерактивный калькулятор и рекомендуемые действия. Включён отдельный модуль `risk_model.py` с тестами; все CPC, клики и доли затронутого трафика вымышленные.
- **О решении:** границы MVP и предлагаемая промышленная архитектура.
- **Скриншоты:** `capture_pages.py` сохраняет пять настоящих экранов локально запущенного приложения в PNG.

В проекте **12 демонстрационных лендингов и искусственная история проверок**. Это не мониторинг настоящих банковских страниц. Текущий MVP не делает фоновые проверки 24/7, не умеет эмулировать реальные браузеры и не отправляет формы. «Покрытие платформ» на обзоре — **план**, а не результаты физических тестов.

## Быстрый запуск на Mac (VS Code)

Открой папку проекта в VS Code и открой встроенный терминал.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Открой `http://localhost:8501`. Если предыдущая версия приложения уже запущена, **останови её в терминале сочетанием Control + C**, прежде чем запускать новую.

Если `.venv` уже создан в **этой же папке**, первые две команды создания окружения повторять не нужно. Достаточно активировать его, установить зависимости и запустить Streamlit.

## Сохранить экраны для Word/PDF

В отдельном терминале из папки проекта с активированным `.venv`:

```bash
python -m playwright install chromium
python capture_pages.py
```

Скрипт **сам запускает отдельную копию приложения** на свободном порту, открывает пять разделов и сохраняет:

```text
report/screenshots/
  01_obzor.png
  02_lendingi.png
  03_proverka_url.png
  04_incidenty.png
  05_biznes_riski.png
```

Это **скриншоты работающего интерфейса**, а не сгенерированные картинки. Полная высота экрана сохраняется; при вставке в PDF можно обрезать по необходимой области и добавить подпись «Прототип. Демонстрационные данные».

## Структура

```text
landing-monitor-design-v3/
  app.py               # страницы и интерфейс
  checker.py           # защищённая ручная HTTP-проверка
  risk_model.py        # расчёты рекламного риска (синтетические данные)
  storage.py           # SQLite и синтетические примеры
  capture_pages.py     # экспорт скриншотов через Playwright
  .streamlit/config.toml
  requirements.txt
  report/screenshots/  # результаты экспорта
  tests/test_checker.py
```

При первом запуске создаётся `storage/monitor.sqlite3`. Если переезжаешь со старой версии проекта и **нужно сохранить свои ручные проверки**, можно остановить оба приложения и перенести файл `storage/monitor.sqlite3` из старой папки в новую. Иначе новая версия создаст чистую локальную базу с демонстрационными данными.

## Что важно для бизнес-кейса

Пользователю рекламной аналитики нужно не просто увидеть ошибку `500`, а понять, **какая страница, на какой платформе, в какой кампании и кто должен реагировать**. Полная версия должна уметь круглосуточно проверять загрузку страницы в браузерах и безопасное оформление тестовой заявки, а также отправлять подтверждённые инциденты ответственным. Эти возможности описаны как требования, а не как уже реализованные функции.

## Ограничения безопасности

Используй ручную HTTP-проверку только для публичных HTTPS-сайтов, на проверку которых есть разрешение. Не выкладывай локальную базу с адресами и историей проверок в публичный репозиторий. В приложении есть базовые ограничения адресов, но локальный MVP **не следует выставлять в публичный доступ как сервис произвольной проверки URL**.

## Особенность: бизнес-приоритет на основе рекламного риска

Обычные мониторинги показывают технические ошибки. В Landing Monitor предложен сценарий, который связывает технический сбой с кампанией и оценкой рекламных расходов под риском. Смысл такой оценки — помочь команде решить, какой инцидент разбирать раньше. Формула: `клики в час × CPC × условная доля затронутых кликов × длительность сбоя в часах`.

Это **не оценка фактических финансовых потерь**, поскольку в ней нет реальных расходов, конверсии, атрибуции заявок и эффекта от остановки кампании. Система не управляет рекламой автоматически; рекомендации являются вариантами действий для ответственного специалиста. В целевой архитектуре данные о кликах и CPC должны поступать из рекламной системы, а правила приоритетов и эскалации согласовываются с владельцами бизнеса.
